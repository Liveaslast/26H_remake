# Task1 5 ms 调参复盘（2026-09-27）

本文是 `Data/TestRecords/` 中 2026-09-27 Task1 CSV 的配套案例记录，不是日常操作入口。它记录 Task1 `0 → +5 → -5 cm` 的实机诊断，并保留可复用的分析方法：先用逐 5 ms 数据确认控制链路，再通过现有串口接口单变量调整，最后用下一轮数据验证因果。当前命令和入口以 [Diagnostics README](../../Diagnostics/README.md) 为准。

## 1. 约束与真实来源

- 正式视觉、串口和下位机行为必须以实际代码及 CSV 为准，不能仅凭 README 猜测。

- `task init` 负责停机、零点和 22°平衡角；Task1 的 BBP/BPUSH 参数由 `startTask(Task1)` 加载，两者不能混为一谈。

关键源码：

## 2. 采集与分析要求

入口：

```powershell
python Diagnostics\APP\run_task1.py --port COM26 --output <csv>
python Diagnostics\APP\analyze_task1.py <csv>
```

每条约 5 ms 控制记录至少同时检查：

```text
时间t | 坐标x | 速度v | 实际电机角 | 目标角 | BBP角 | BPUSH角 | 标志位 | seq_stage
```

不能只看最大超调或最终坐标。必须回答：

1. BBP从哪个坐标、速度开始？
2. 穿过目标时的坐标、速度和剩余制动角是多少？
3. BBP/BPUSH交接时目标角是否发生阶跃？实际电机多久跟随？
4. 速度何时反号？反号时球在目标前还是目标后？
5. BPUSH退出是因为速度、位置窗口、死区，还是阶段已经切换？
6. 最终静止时是否仍有控制输出、序列是否真正完成？

视觉坐标在个别 5 ms 内可能跳动约 0.2 cm，因此单个极值不能独立定性；应结合连续坐标、滤波速度、角度和状态标志判断。

## 3. 串口覆盖顺序

Task1启动时会重新装载默认profile，因此覆盖命令必须排在 `task 1` 后。采集脚本按以下顺序发送：

```text
task 1
bbp ...       # 短距离BBP
bbpd ...      # 长距离BBP
bbpn ...      # 负向BBP独立上限
bpushp ...    # 正向BPUSH
bpushm ...    # 负向BPUSH
```

相关入口参数：

```text
--bbp-short KP MARGIN_CM MAX_DEG DIST_CM
--bbp-long KP MARGIN_CM MAX_DEG DIST_CM
--bbp-negative-max MAX_DEG
--bpush-positive WINDOW_CM VX_CM_S PUSH_DEG MAX_DEG
--bpush-negative WINDOW_CM VX_CM_S PUSH_DEG MAX_DEG
```

BPUSH命令的第四个值当前由固件解析但控制器不使用；实际固定脉冲角由第三个值决定。

## 4. 正向 0 → +5 cm：从“刹不住”定位到BPUSH二次加速

### 4.1 默认基线

文件：`task1_20260927_131640.csv`

- `+5`首次穿越速度约 `10.71 cm/s`。
- 最大坐标约 `+6.40 cm`，超调约 `1.40 cm`。
- 默认短距离BBP上限 `2.5°` 长时间饱和，制动开始偏晚且不足。

### 4.2 增大短距离制动

临时覆盖：

```text
bbp 0.35 3.0 4.0 5.0
```

文件：`task1_bbp_m3_max4_20260927_133205.csv`

BBP本身明显有效：

- `t=0.611 s`：`x=2.15 cm, v=8.45 cm/s`，BBP开始。
- `t=1.338 s`：`x=4.75 cm, v=1.04 cm/s`，球已基本刹住。

但随后正向BPUSH在目标前接管：

- `t=1.343 s`：目标角从约 `25.30°` 跳到 `28.50°`。
- 球重新加速，最大坐标约 `+6.48 cm`。

因此不能把“最终仍超调”误判为BBP还不够强；真正原因是BPUSH二次加速。

### 4.3 关闭正向BPUSH验证因果

```text
bpushp 0 0 0 0
```

文件：`task1_bbp_m3_max4_bpushp_off_20260927_133954.csv`

- 最大坐标约 `+5.03 cm`，超调约 `0.03 cm`。
- BBP从 `x=2.11 cm, v=8.42 cm/s` 工作到 `x=4.89 cm, v=0.66 cm/s`。
- 正向BPUSH全程未触发，随后正常进入负向阶段。

这证明原正向问题主要是默认BPUSH接管时机/强度，不是识别链路或电机跟随失败。

## 5. 负向 +5 → -5 cm：不要只看最低坐标

### 5.1 默认长距离制动过早

默认长距离margin为 `5.5 cm`，负向BBP还有独立 `negative_max=5.5°`。基线常在 `-4 cm`附近已经被强力制停并回弹。

先只把长距离margin改为 `4.5 cm`：

```text
bbpd 0.45 4.5 4.0 10.0
```

文件：`task1_neg_margin4p5_20260927_134407.csv`

- 最低坐标改善到约 `-4.91 cm`。
- 但默认负向BPUSH在 `x=-4.62 cm, v=-0.82 cm/s` 提前启动。
- 原因是BPUSH使用 `abs(error)` 与 `abs(v)`，不要求已经越过 `-5`。
- 锁存后BBP不能及时重新接管，最终停在约 `-3.89 cm`。

### 5.2 关闭两侧BPUSH暴露BBP回弹

文件：`task1_both_bpush_off_retry_20260927_134940.csv`

- 最低坐标约 `-5.17 cm`。
- `x=-5.01 cm`时仍有 `v=-9.05 cm/s`、BBP约 `+4.73°`。
- 到 `x=-4.66 cm, v=-0.39 cm/s`时，序列满足 `±0.7 cm / ±0.7 cm/s`完成条件，BBP退出。
- 随后回弹并最终停在 `-2.62 cm`。

说明“到过-5”不等于“在-5停住”；必须分析穿越速度、剩余BBP角和退出后的回弹。

### 5.3 显式设置负向上限

`bbpd ... MAX_DEG=4.0`并不会限制负向到4°，因为固件的独立 `negative_max=5.5°`会覆盖它。必须同时发送：

```text
bbpn 4.0
```

文件：`task1_negmax4_20260927_135247.csv`

- BBP实际峰值降为 `4.0°`。
- 穿过 `-5.05 cm`时仍有 `-11.00 cm/s`。
- 最低约 `-5.67 cm`，之后仍明显回弹。

单纯降低上限会增加穿越速度和负向超调，不能代替合理的终端交接。

## 6. BPUSH为何提前、为何很快结束

BPUSH的实质是固定角度摩擦突破脉冲，不是连续位置闭环。触发需要：

- `abs(error)`在窗口内且大于死区；
- `abs(v)`低于速度阈值；
- BBP已退出。

它不判断速度方向，也不限定目标前/目标后。因此：

- 阈值过低时，球开始回弹后速度很快超过阈值，BPUSH错过接管。
- 阈值提高后，可能在目标前低速阶段提前接管。
- 窗口过小时，球一旦回到 `-4.x`便离开窗口，BPUSH无法再次启动。
- 窗口过大时，BPUSH可能长期锁存，序列迟迟不结束。

文件 `task1_bpushm_v2_20260927_140607.csv` 中，`window=0.7, vx=2.0`：

- BPUSH从 `x=-4.75 cm, v=-1.38 cm/s`提前启动。
- 到 `x=-4.24 cm, v=+3.51 cm/s`退出。
- 最终停在 `-4.07 cm`；误差 `0.93 cm`已超出0.7 cm窗口，不能再次接管。

## 7. 本轮接受的实验参数与剩余边界

最终试验命令使用：

```text
bbp    0.35 3.0 4.0 5.0
bbpd   0.45 4.5 4.0 10.0
bbpn   4.0
bpushp 0 0 0 0
bpushm 1.0 2.0 2.0 2.0
```

文件：`task1_bpushm_w1_v2_20260927_141013.csv`

- 正向最终约 `+4.84 cm`，正向最大约 `+4.98 cm`。
- 负向最低约 `-5.21 cm`，最终约 `-4.78 cm`，静止速度为0。
- 负向BPUSH从约 `x=-4.70 cm`开始，后续多次/持续介入，把一度回到约 `-4.0 cm`的球重新推到 `-4.78 cm`。
- 12 s结束时BPUSH仍为 `-2°`、`seq_stage=2`；误差约 `0.22 cm`仍大于0.15 cm死区，所以这是一组“位置效果已接受但控制仍锁存”的实验参数，不能宣称序列逻辑已经自然完成。

如需严格实现“只在已经开始向-4回弹时启动，并在靠近-5后退出”，现有串口参数不够，因为固件只检查绝对速度。需要另行评审下位机触发条件；不要在没有新实机数据时直接固化。

## 8. 后续调参准则

1. 一轮只改一个可解释变量；若必须联动，明确说明因果假设。
2. 参数命令、CSV文件名和实际生效值必须同时记录。
3. 首先确认视觉有效率和时间基准，再讨论控制参数。
4. 坐标、速度和角度必须同一时间点展示，不能只报速度或最终极值。
5. BBP重点看开始点、穿越目标时速度、剩余角度和退出点。
6. BPUSH重点看首次触发位于目标前还是目标后、速度方向、持续时间、退出原因和是否锁存。
7. `seq_stage=0`才表示序列状态机完成；位置看似稳定但阶段未完成，需要单独标记。
8. 串口临时覆盖不等于固件默认值已修改；正式固化前必须再次完整复测。
