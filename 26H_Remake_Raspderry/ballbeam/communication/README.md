# Pi–MCU线上协议

本文只定义线上帧与确认语义；字段顺序、CRC和缩放以 `protocol.py` 与MCU `PiProtocol` 源码为准，不描述线程调用链。

## 帧与单位

| 方向 | 编号 | 字节数 | 内容 |
|---|---|---:|---|
| Pi → MCU | `0x06` | 6 | 模式请求：seq、mode |
| MCU → Pi | `0x86` | 7 | 模式应答：seq、mode、result |
| Pi → MCU | `0x07` | 21 | RUN：视觉、任务号、请求号 |
| MCU → Pi | `0x84` | 37 | RUN：遥测及任务结果 |
| Pi → MCU | `0x08` | 39 | TUNING：视觉、任务/请求、PID、目标速度、参数版本 |
| MCU → Pi | `0x85` | 39 | TUNING：遥测、任务及参数结果 |

模式 `RUN=1 / TUNING=2`；模式应答 `0=成功、1=失败`。多字节小端；位置/速度/角度每整数单位为0.01，PID为0.0001，时间为ms。MCU及Support独立客户端必须配套更新，不兼容旧42/44字节遥测。

## 请求和确认

- 两模式task 0为初始化；RUN/task 1为正式任务，TUNING/task 1为球速阶跃。
- `request_seq=0` 不执行任务，包括task 0；新的非零请求号触发一次尝试，重复周期包不重复启动。
- `seq` 是成功写出后递增的包号，`request_seq` 标识任务请求，`revision` 标识配置版本，不是图像编号。不保证跨重启恰好执行一次。
- `select_mode` 等待匹配0x86，拒绝、写失败或超时返回失败，不自动重发。
- `request_task` 只等本地登记并返回请求号；真正发送在后续周期包中完成。
- 球速参数先配置并确认版本，再提交启动请求。配置时线上请求号置0，运行中拒绝新版本；参数确认不表示运动开始。

| 查询接口 | 先匹配 | 成功位 |
|---|---|---|
| `task_result(request_seq)` | 遥测任务请求号 | `status & (1 << 3)` |
| `parameters_result(revision)` | 遥测参数版本 | `status & (1 << 4)` |

无匹配记录返回 `None`；匹配后返回成功位的布尔值。查询读取缓存，不发送查询包。任务成功表示初始化/启动请求成功，不表示运动完成；模式确认不替代机械、参数和视觉准备。

视觉发送时超过100ms清除有效位。本地串口写成功不表示MCU已接收或执行；通信不保证硬实时或跨重启恰好一次。
